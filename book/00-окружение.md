# Глава 0. Проверка окружения перед стартом

> **Цель главы:** до первой установки понять, что за машина, подходит ли она, что уже
> установлено и что будет мешать. Ничего не устанавливаем — только смотрим и записываем выводы.
>
> **Нужно из прошлых глав:** ничего, это первая глава.
> **Время:** 10–15 минут. **Права:** обычный пользователь; `sudo` понадобится один раз.

---

## Зачем это в проде

В проде никто не заходит на сервер и не начинает «ставить Docker». Сначала идёт подготовка
хоста: проверить модель/версию ОС, ядро, cgroup, ресурсы, сеть, порты, права, наличие
конфликтующих пакетов. Обычно это оформлено в Ansible-роль или в cloud-init, и если проверка
не прошла — деплой падает **до** установки, а не в три часа ночи.

Пять реальных граблей, которые ловятся именно на этом шаге:

| Грабли | Как проявляются | Ловится командой |
|---|---|---|
| cgroup v1 вместо v2 | Docker живёт, но `--cpus`/`-m` работают странно, будущий Kubernetes ругается | `stat -fc %T /sys/fs/cgroup` |
| Нет места в `/var/lib/docker` | через неделю «no space left on device» и мёртвые контейнеры | `df -h /var` |
| Не та архитектура (arm64 вместо amd64) | образ `exec format error` | `uname -m`, `dpkg --print-architecture` |
| Уже установлен `docker.io` из репозитория Ubuntu | `apt install docker-ce` конфликтует с ним | `dpkg -l | grep docker` |
| Порт 80/8080/5432 уже занят | контейнер стартует и сразу умирает, в логах «address already in use» | `ss -ltnp` |

Дальше — по шагам. Для каждой команды: что она делает, зачем нужна и **проверка** — как
убедиться, что мы правильно её прочитали.

## 0.1. Рабочий каталог лаборатории

Глава 0 — первая, поэтому блока «Возврат в начало» здесь нет: восстанавливать нечего.
Всю лабораторию держим в одном месте, чтобы в конце курса снести одной командой.

```bash
mkdir -p ~/docker-lab/reports
```

**Что произошло:** создан каталог `~/docker-lab` и в нём подкаталог `reports` для отчётов о
проверках.

**Проверка:**

```bash
ls -la ~/docker-lab && echo "OK: $HOME/docker-lab существует"
```

**Ожидаемо:** в списке есть каталог `reports`, строка `OK: /home/alexey/docker-lab существует`.

## 0.2. Какая ОС и какое ядро

```bash
cat /etc/os-release
```

**Что видим:** имя дистрибутива, версия, кодовое имя (`VERSION_CODENAME`). Кодовое имя
понадобится в главе 1 — из него собирается URL репозитория Docker.

**Почему это важно:** Docker официально поддерживает конкретные версии дистрибутивов.
Плюс версия ОС определяет, какой ветке репозитория соответствуешь ты.

**Проверка:**

```bash
lsb_release -ds && lsb_release -cs && uname -r && hostnamectl | grep -E 'Operating System|Kernel|Architecture'
```

**Ожидаемо на этой машине:**

```
Ubuntu 26.04.1 LTS
resolute
7.0.0-38-generic
 Operating System: Ubuntu 26.04.1 LTS
           Kernel: Linux 7.0.0-38-generic
     Architecture: x86-64
```

У тебя версии будут другими — важно, что ОС Ubuntu 24.04/26.04 (или другой LTS),
а ядро не древнее 5.15. Ядро ≥ 5.10 — минимум для нормальной работы современных
возможностей Docker; всё, что новее, только лучше.

## 0.3. Архитектура: amd64 или arm64

```bash
uname -m
```

**Что видим:** `x86_64` (Intel/AMD) или `aarch64` (ARM). Критично, потому что образ
`postgres:18-alpine` — это **набор** слоёв под разные архитектуры; Docker сам выберет нужный.
Но если ты собираешь образ на ARM-ноутбуке и тащишь в amd64-кластер — «exec format error».

**Проверка:**

```bash
dpkg --print-architecture && uname -m | sed 's/x86_64/amd64/; s/aarch64/arm64/'
```

**Ожидаемо:** обе строки совпадают (`amd64`/`amd64` или `arm64`/`arm64`).
На этой машине: `amd64` и `amd64`.

---

## 0.4. Это физическая машина, виртуалка или WSL?

```bash
systemd-detect-virt
```

**Что видим:** `none` — железо или «плоская» ВМ без индикаторов; `kvm`/`vmware`/`oracle` —
виртуалка; `wsl` — Windows-подсистема.

**Зачем:** Docker Desktop и WSL имеют свои особенности (проброс портов, права на файлы,
`host.docker.internal`). Мы строим курс на «настоящем» Linux с systemd — так же, как на
прод-сервере. Если у тебя WSL — большинство команд главы 1 не изменится, но система
инициализации там другая, часть проверок (`systemctl is-active docker`) будет вести себя иначе.

**Проверка:**

```bash
cat /proc/1/comm && uname -r | grep -qi microsoft && echo "WSL" || echo "не WSL"
```

**Ожидаемо:** `systemd` (значит система инициализации — systemd, как на сервере) и `не WSL`.

## 0.5. cgroup v2 — главная невидимая проверка

```bash
stat -fc %T /sys/fs/cgroup && cat /proc/self/cgroup
```

**Что видим:** тип файловой системы, смонтированной в `/sys/fs/cgroup`.
`cgroup2fs` — это cgroup **v2** (то, что нужно). `tmpfs` — значит v1 (устаревшая схема).

**Зачем:** cgroup — механизм ядра, которым Docker ограничивает контейнер по CPU и памяти.
На v2 `docker run -m 512m` и `--cpus 0.5` работают предсказуемо; на v1 часть лимитов
игнорируется. Kubernetes вообще объявил v1 устаревшим.

**Проверка:**

```bash
test "$(stat -fc %T /sys/fs/cgroup)" = "cgroup2fs" && echo "cgroup v2: OK" || echo "cgroup v1: нужно включать v2"
```

**Ожидаемо:** `cgroup v2: OK`. На этой машине так и есть.

Ещё две вещи, которые понадобятся позже (глава 4 — сети контейнеров):

```bash
ip -o link show | grep -c . ; sysctl net.ipv4.ip_forward kernel.unprivileged_userns_clone 2>/dev/null
```

**Что видим:** количество сетевых интерфейсов и два параметра ядра. `net.ipv4.ip_forward = 0`
— нормально: Docker включит форвардинг сам, когда поднимет свой первый бридж. Но знать, что
было `0`, полезно: если после установки Docker там всё ещё `0` — что-то не так.

## 0.6. Железо: CPU, память, диск, swap

```bash
nproc && free -h | sed -n '1,2p' && df -h /var/lib && swapon --show
```

**Что видим:** число доступных ядер, объём RAM (и сколько реально свободно), место на разделе,
где будет жить `/var/lib/docker`, и включён ли swap.

| Ресурс | Для этой лабы (Docker) | Для глав 10+ (мини-Kubernetes) | Почему |
|---|---|---|---|
| CPU | 2 ядра | 4 ядра | сборка образов и мини-кластер любят ядра |
| RAM | 4 GB | 8 GB | `postgres` + `rabbitmq` + кластер |
| Диск | 20 GB свободно | 60 GB | образы и слои растут быстро |
| Swap | можно | лучше выключить | kubelet требует `swapoff` |

**Проверка:**

```bash
nproc; free -m | awk '/Mem:/{printf "RAM: %d MB, доступно: %d MB\n", $2, $7}'
df -h / | tail -1; lsblk -d -o NAME,SIZE,ROTA,TRAN | head -5; ulimit -n
```

**Ожидаемо на этой машине:** `16`, `RAM: 14789 MB`, свободно `~319G` на `/`, диск `nvme`
(`ROTA=0` → SSD), `ulimit -n` = 1024. `swapon --show` покажет 4 GB swap — в главе 10 мы его
выключим, сейчас не трогаем.

## 0.7. Сеть, DNS и порты

```bash
ip -br a && ip route | sed -n '1,3p'
```

**Что видим:** активный интерфейс (адрес вида `192.168.x.y`) и шлюз по умолчанию.

**Проверка доступа в интернет и DNS** (без этого не скачается ни образ, ни пакет):

```bash
getent hosts download.docker.com | head -2 && curl -sI https://download.docker.com/linux/ubuntu/dists/ | head -1
```

**Ожидаемо:** строка вида `2600:9000:... cloudfront.net download.docker.com` и `HTTP/2 200`.

**Порты, которые нам понадобятся:** 8080 (веб), 5432 (Postgres), 5672 и 15672 (RabbitMQ),
30000–32767 (NodePort в Kubernetes).

```bash
ss -ltn | grep -E ':(80|8080|5432|5672|15672)\b' || echo "нужные порты свободны"
env | grep -iE '_proxy=' || echo "прокси не задан"
```

**Ожидаемо:** `нужные порты свободны` и `прокси не задан`.
Если какой-то порт занят — запомни чем именно: в лабе ты просто возьмёшь другой порт, это
нормальная ситуация.

> **В проде:** порт 5432 у базы данных никогда не публикуют наружу — только во внутреннюю
> сеть. Но знать, кто слушает локально, нужно до того, как начнёшь публиковать.

## 0.8. Права: `sudo` и группа `docker`

```bash
id -nG && getent group docker || echo "группы docker ещё нет (появится после установки)"
sudo -v && echo "sudo: пароль принят"
```

**Почему:** Docker поставится только через `sudo`. А группа `docker` (её создаст пакет) даёт
право работать с демоном без `sudo` — удобно, и это же классическая дыра: членство в группе
`docker` = фактически root на хосте.

**Ожидаемо на этой машине:** в списке групп есть `sudo`, `docker` — нет (пока); после `sudo -v`
будет запрос пароля, затем `sudo: пароль принят`.

## 0.9. Что уже установлено, а чего нет

```bash
for t in curl wget git make jq snap dotnet; do printf '%-8s %s\n' "$t" "$(command -v $t || echo 'НЕТ')"; done
```

```bash
apt-cache policy docker.io docker-ce docker-compose-v2 | grep -E '^[a-z]|Candidate'
```

**Что это значит:** `docker-ce` → `Candidate: (none)` — официальный репозиторий Docker не
подключён, а `command -v docker` ничего не найдёт: **Docker не установлен вообще**.
`docker.io` в репозитории Ubuntu есть (версия `29.1.3`) — это второй способ установки из
главы 1.

**Проверка «Docker точно нет»:**

```bash
command -v docker || echo "docker: не установлен"
systemctl list-unit-files | grep docker || echo "юнитов docker нет"
```

## 0.10. Отчёт одной командой (сохраняем в файл)

Ручные проверки — для понимания. В проде это делает скрипт (или Ansible-роль). Соберём отчёт:

```bash
{
  echo "== отчёт окружения $(date -Is) =="
  lsb_release -ds; lsb_release -cs; uname -r; dpkg --print-architecture
  echo "virt: $(systemd-detect-virt); pid1: $(cat /proc/1/comm)"
  echo "cgroup: $(stat -fc %T /sys/fs/cgroup)"
  echo "CPU: $(nproc)"; free -h | sed -n 2p; df -h / | tail -1
  ip -br a | grep -v -w DOWN
} | tee ~/docker-lab/reports/env-report.txt
```

**Проверка:**

```bash
cat ~/docker-lab/reports/env-report.txt && wc -l < ~/docker-lab/reports/env-report.txt
```

**Ожидаемо:** файл на 10–15 строк с ОС, ядром, архитектурой, cgroup, CPU/RAM/диском и
интерфейсами. Это «фотография» машины до установки Docker — после откатов глав удобно
сравнивать с ней.

## 0.11. Чек-лист самопроверки (глава 0)

| Вопрос | Ответ командой |
|---|---|
| Какая ОС и её кодовое имя? | `lsb_release -ds; lsb_release -cs` |
| Какая архитектура? | `dpkg --print-architecture` |
| Какая система инициализации? | `cat /proc/1/comm` |
| cgroup v1 или v2? | `stat -fc %T /sys/fs/cgroup` |
| Сколько CPU и RAM? | `nproc; free -h` |
| Сколько места там, где будет жить Docker? | `df -h /var/lib` |
| Есть ли DNS и интернет? | `getent hosts download.docker.com; curl -sI https://download.docker.com \| head -1` |
| Свободны ли порты 8080/5432/5672/15672? | `ss -ltn \| grep -E ':(8080\|5432\|5672\|15672)\b'` |
| Есть ли право на `sudo`? | `sudo -v` |
| Установлен ли уже Docker? | `command -v docker \|\| echo нет` |

Если отвечаешь без подглядывания — глава закрыта.

## 0.14. Типичные ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| `systemd-detect-virt` → `wsl` | работаешь в WSL | команды главы 1 отличаются; лучше взять реальную Linux-машину или ВМ |
| `stat -fc %T /sys/fs/cgroup` → `tmpfs` | включён cgroup v1 | добавить параметр ядра `systemd.unified_cgroup_hierarchy=1` |
| `df -h /` показывает < 20 GB | мало места | освободить или перенести `/var/lib/docker` на другой диск (глава 1, `data-root`) |
| `apt-cache policy docker-ce` → `(none)` | репозиторий Docker не подключён | это нормально до главы 1 |
| `curl: (6) Could not resolve host` | нет DNS / VPN | проверить `resolvectl status`, `/etc/resolv.conf` |
| `sudo: interactive authentication is required` | запуск из скрипта без TTY | выполнять в обычном терминале |
